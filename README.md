# Onno Subscriptions

Тестовое задание, реализованное с использованием фреймворка **onno**.

Приложение представляет собой простой сервис управления подписками: клиент может пополнять лицевой счёт, оформлять подписки на один или несколько тарифов, а система учитывает списания и выручку по тарифам.

## Технологии

- Java 21
- Spring Boot 3.4.4
- onno framework 2.0.0
- Spring Data JDBC
- H2
- JobRunr
- Gradle

## Основные возможности

### Клиенты

Для клиента хранятся:

- статус
- email
- телефон
- дата регистрации

### Тарифы

Для каждого тарифа задаются:

- цена за период
- длительность периода в днях
- доступность для оформления подписки

### Платежи

Платёж пополняет лицевой счёт клиента при проведении документа.

### Подписки

Одна подписка может содержать несколько строк с разными тарифами.

Каждая строка содержит:

- тариф
- количество периодов
- цену
- сумму

При сохранении подписки система автоматически:

- получает актуальную цену из выбранного тарифа
- рассчитывает сумму каждой строки
- рассчитывает общую стоимость подписки
- рассчитывает дату окончания подписки
- определяет срок подписки по самой длинной строке

Пример:

- Basic: 30 дней × 2 периода = 60 дней
- Annual: 365 дней × 1 период = 365 дней

Итоговая длительность подписки будет составлять 365 дней.

## Бизнес-правила

При сохранении подписки проверяется:

- выбран ли клиент
- есть ли хотя бы одна строка
- количество периодов больше нуля
- все выбранные тарифы доступны для оформления

Подписка не может быть проведена, если на лицевом счёте клиента недостаточно средств.

Отменённые подписки не создают движений по регистрам.

## Регистры

### Customer Accounts

Регистр накопления остатков.

Используется для хранения текущего баланса клиента.

- платёж создаёт приход
- подписка создаёт расход

Отрицательный баланс запрещён.

### Tariff Revenue

Регистр накопления оборотов.

Используется для учёта выручки по:

- тарифу
- клиенту

Ресурсы:

- сумма
- количество периодов

## Автоматическое обновление статусов подписок

Для автоматического обновления статусов используется фоновая задача.

В зависимости от дат подписка переводится в соответствующее состояние:

- действующая подписка → `ACTIVE`
- подписка с истёкшей датой окончания → `EXPIRED`
- будущая подписка остаётся `DRAFT`
- подписка со статусом `CANCELLED` не изменяется

Фоновая задача реализована с использованием:

- `@ScheduledJob`
- `BackgroundTask`
- JobRunr

## Тесты

Автоматические тесты покрывают основную бизнес-логику приложения:

- получение цены из тарифа
- расчёт суммы строки
- расчёт общей стоимости подписки
- расчёт даты окончания
- определение максимальной длительности
- обязательность клиента
- наличие хотя бы одной строки
- проверку `periods > 0`
- запрет недоступного тарифа
- отсутствие движений у отменённой подписки
- автоматическое обновление статусов подписок
