# Onno Subscriptions

Тестовое задание на разработку сервиса управления подписками с использованием **onno framework**.

Приложение позволяет:

- создавать клиентов и тарифы;
- пополнять лицевой счёт клиента;
- оформлять подписки на один или несколько тарифов;
- автоматически рассчитывать стоимость и срок подписки;
- учитывать остатки на лицевых счетах;
- учитывать выручку по тарифам и клиентам;
- автоматически обновлять статусы подписок по датам.

## Технологии

- Java 21
- Spring Boot 3.4.4
- onno framework 2.0.0
- Spring Data JDBC
- H2 Database
- JobRunr
- Gradle

## Функциональность

### Клиенты

Для клиента хранятся:

- статус;
- email;
- телефон;
- дата регистрации.

### Тарифы

Для тарифа задаются:

- цена за один период;
- длительность одного периода в днях;
- доступность тарифа для оформления подписки.

### Платежи

Платёж используется для пополнения лицевого счёта клиента.

При проведении платежа в регистре `Customer Accounts` создаётся приход на сумму платежа.

### Подписки

Одна подписка может содержать несколько строк с разными тарифами.

Каждая строка содержит:

- тариф;
- количество периодов;
- цену за период;
- сумму строки.

При сохранении подписки система автоматически:

- получает актуальную цену из выбранного тарифа;
- рассчитывает сумму каждой строки;
- рассчитывает общую стоимость подписки;
- рассчитывает дату окончания подписки.

Дата окончания определяется по строке с максимальной длительностью.

Пример:

- Basic: 30 дней × 2 периода = 60 дней;
- Annual: 365 дней × 1 период = 365 дней.

Итоговая длительность подписки в этом случае составляет 365 дней.

## Бизнес-правила

При работе с подпиской проверяется:

- клиент должен быть выбран;
- в подписке должна быть хотя бы одна строка;
- количество периодов должно быть больше нуля;
- выбранные тарифы должны быть доступны для оформления.

Подписка не может быть проведена, если на лицевом счёте клиента недостаточно средств.

Подписка со статусом `CANCELLED` не создаёт движений по регистрам.

## Регистры

### Customer Accounts

Регистр накопления остатков.

Используется для хранения текущего баланса клиента.

Движения:

- проведение платежа создаёт приход;
- проведение подписки создаёт расход.

Отрицательный баланс запрещён.

### Tariff Revenue

Регистр накопления оборотов.

Используется для учёта выручки по:

- тарифу;
- клиенту.

Ресурсы:

- сумма;
- количество периодов.

## Автоматическое обновление статусов

Для обновления статусов подписок реализована фоновая задача с использованием:

- `@ScheduledJob`;
- `BackgroundTask`;
- JobRunr.

Статусы обновляются по датам:

- если текущая дата находится внутри периода подписки — `ACTIVE`;
- если дата окончания уже прошла — `EXPIRED`;
- если дата начала ещё не наступила — подписка остаётся `DRAFT`;
- подписки со статусом `CANCELLED` не изменяются.

# Запуск приложения

## Требования

Для запуска необходима **Java 21**.

Проверить установленную версию Java можно командой:

```bash
java -version
```

Ожидается версия Java 21, например:

```text
openjdk version "21"
```

Отдельно устанавливать Gradle не требуется: проект содержит **Gradle Wrapper**.

## 1. Клонирование репозитория

```bash
git clone https://github.com/17Joji17/onno-subscriptions.git
cd onno-subscriptions
```

Также проект можно скачать с GitHub как ZIP-архив и распаковать.

## 2. Сборка проекта

Windows:

```powershell
.\gradlew.bat clean build
```

Linux / macOS:

```bash
./gradlew clean build
```

При успешной сборке в конце будет:

```text
BUILD SUCCESSFUL
```

## 3. Запуск

Windows:

```powershell
.\gradlew.bat bootRun
```

Linux / macOS:

```bash
./gradlew bootRun
```

После успешного запуска в консоли появится сообщение вида:

```text
Started OnnoSubscriptionsApplication
```

## 4. Открытие приложения

Открыть в браузере:

```text
http://localhost:8080
```

Данные для входа:

```text
Логин: admin
Пароль: admin
```

## Хранение данных

Для локальной работы используется файловая база данных **H2**.

Файлы базы создаются автоматически в каталоге:

```text
data/
```

Создавать базу данных вручную не требуется.

Схема базы данных создаётся и обновляется средствами onno framework на основе Java-модели приложения.

# Работа с приложением

Ниже приведён основной сценарий проверки приложения.

## 1. Создание клиента

Открыть:

```text
Customers → Customer
```

Создать клиента, например:

```text
Name: Test Customer
Status: Active
Email: test@example.com
Phone: +79990000000
Registration Date: текущая дата
```

Сохранить запись.

## 2. Создание тарифов

Открыть:

```text
Configuration → Tariff
```

Пример тарифа Basic:

```text
Name: Basic
Price Per Period: 990
Period Duration, Days: 30
Available: true
```

Пример тарифа Annual:

```text
Name: Annual
Price Per Period: 9990
Period Duration, Days: 365
Available: true
```

## 3. Пополнение лицевого счёта

Открыть:

```text
Subscriptions → Payment
```

Создать платёж:

```text
Customer: Test Customer
Amount: 20000
Payment Method: Bank Card
```

Сохранить документ и нажать `Post`.

После проведения платежа баланс можно проверить в:

```text
Reports → Customer Accounts
```

## 4. Создание подписки

Открыть:

```text
Subscriptions → Subscription
```

Выбрать клиента:

```text
Customer: Test Customer
```

Добавить строки подписки.

Например:

```text
Tariff: Basic
Periods: 2
```

и:

```text
Tariff: Annual
Periods: 1
```

При сохранении цена, сумма строк, общая стоимость и дата окончания рассчитываются автоматически.

Для этого примера:

```text
Basic:
990 × 2 = 1980

Annual:
9990 × 1 = 9990

Total:
11970
```

Так как Annual имеет наибольшую длительность, дата окончания рассчитывается как:

```text
Start Date + 365 дней
```

## 5. Проведение подписки

После сохранения подписки нажать `Post`.

При проведении:

- стоимость подписки списывается с лицевого счёта клиента;
- выручка записывается в регистр `Tariff Revenue`.

Если денег на лицевом счёте недостаточно, проведение будет отклонено.

## 6. Просмотр отчётов

Открыть раздел:

```text
Reports
```

Доступны:

### Customer Accounts

Показывает текущий баланс клиентов.

### Tariff Revenue

Показывает выручку по тарифам и клиентам, а также количество оплаченных периодов.

## 7. Отмена подписки

Подписка со статусом:

```text
CANCELLED
```

не создаёт движений по лицевому счёту и выручке.

Если уже проведённую подписку изменить на `CANCELLED` и выполнить повторное проведение, предыдущие движения будут отменены, а новые созданы не будут.

# Тесты

В проекте реализованы автоматические тесты основной бизнес-логики.

Проверяются:

- получение цены строки из тарифа;
- расчёт суммы строки;
- расчёт общей стоимости подписки;
- расчёт даты окончания;
- выбор максимальной длительности среди строк;
- обязательность клиента;
- наличие хотя бы одной строки подписки;
- проверка `periods > 0`;
- запрет недоступного тарифа;
- отсутствие движений для отменённой подписки;
- автоматическое обновление статусов подписок.

Windows:

Linux / macOS:

При успешном выполнении:

```text
BUILD SUCCESSFUL
```


# Особенности реализации

Приложение построено на типизированной Java-метамодели **onno framework**.

На основании Java-классов фреймворк формирует:

- схему базы данных;
- миграции;
- REST API;
- CRUD-интерфейс;
- формы;
- списки сущностей;
- отчёты по регистрам.

Поэтому стандартные DTO, CRUD-контроллеры, SQL-таблицы и формы вручную не создавались.
